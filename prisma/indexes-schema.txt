model Inventory {
  // ... existing fields
  
  // Single column indexes
  @@index([sku], name: "idx_inventory_sku")
  @@index([warehouseId], name: "idx_inventory_warehouse")
  @@index([status], name: "idx_inventory_status")
  @@index([createdAt], name: "idx_inventory_created")
  @@index([updatedAt], name: "idx_inventory_updated")
  
  // Composite indexes for common queries
  @@index([warehouseId, status], name: "idx_inventory_warehouse_status")
  @@index([status, quantity], name: "idx_inventory_status_qty")
  @@index([reorderPoint, quantity], name: "idx_inventory_reorder")
  
  // Full-text search
  @@fulltext([name, description], name: "idx_inventory_search")
}

/*
INDEX SELECTION RULES:

1. WHERE clauses: Create indexes for frequently filtered columns
2. JOIN operations: Index foreign key columns
3. ORDER BY: Index columns used for sorting
4. GROUP BY: Consider composite indexes
5. Full-text search: Use @@fulltext for text search

COMPOSITE INDEX ORDER:
- Most selective column first
- Equality before range
- ORDER BY columns last

AVOID:
- Too many indexes (slows INSERT/UPDATE)
- Indexes on low-cardinality columns (status with 2-3 values)
- Duplicate indexes
- Unused indexes

MONITORING:
- Check query performance regularly
- Use EXPLAIN ANALYZE in PostgreSQL
- Monitor slow query logs
- Review index usage statistics

MAINTENANCE:
- Rebuild indexes periodically
- Update statistics
- Remove unused indexes
- Test index changes in staging first
*/
